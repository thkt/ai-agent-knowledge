# AIエージェント活用ナレッジ

AIエージェント運用で下した判断について、採用した理由、却下した案、検証結果を人間が読める形で残します。

このリポジトリは公開していますが、想定する読み手は社内のメンバーと将来の自分です。エージェントが読み込む設定(rules / skills)の正本は `~/.claude` にあり、このリポジトリには置きません。

## 書くもの

| 書くもの | 書かないもの |
| --- | --- |
| 自分たちで検証した判断と、その根拠 | `knowledge/` に、外部記事を読んだだけで検証していない内容 |
| 試して採用しなかった案と、その理由 | ツールの使い方の網羅。公式ドキュメントに任せる |
| 検証日、検証したモデル、再現手順 | 顧客名、案件名、認証情報などの機密 |
| 外部記事の考え方と、その根拠を照合した結果。`sources/` に置く | 照合日のない要約 |
| 検証する前の考察。`notes/` に置く | `notes/` に、発言と推測を区別していない考察 |

## ページを追加する

1. `knowledge/_template.md` を `knowledge/<内容を表す名前>.md` にコピーする。
2. 見出しをすべて埋める。埋められない見出しには、足りない材料を書く。
3. 冒頭の TL;DR に、結論、根拠の数字、確かめていないことを3〜5行で書く。
4. 検証日とモデルを必ず書く。読者はこの2つで、知見が今も再現するかを判定する。

## 外部記事を整理する

`sources/` のページは、記事の主張と根拠の照合結果であり、自分たちの判断ではありません。記事や投稿の原文は転載せず、要点の要約とリンクで扱います。

1. `sources/<内容を表す名前>.md` を作る。
2. 冒頭に、出典、公開日、照合日、照合した範囲を書く。
3. 冒頭の文の次に TL;DR を置き、中心の主張、照合で分かったこと、確かめていないことを3〜5行で書く。
4. 考え方ごとに、記事が挙げる根拠と照合の結果を書く。照合できなかったものは「未照合」と書く。
5. 照合の手順を、読者が同じ結果を得られる粒度で書く。
6. 考え方を判断として採用したら、`knowledge/` にページを書き、`sources/` のページを根拠として引く。

## 考察を残す

`notes/` のページは、検証する前の考察であり、自分たちの判断ではありません。社内で聞いた話を材料にするときは、人名、顧客名、Slack などの社内の URL を書きません。

1. `notes/<内容を表す名前>.md` を作る。
2. 冒頭に、出典、考察日、考察の材料、検証の有無を書く。
3. 主張ごとに、出典の発言、手元の資料、推測のどれに基づくかを書く。
4. 検証したら、`knowledge/` にページを書き、`notes/` のページを根拠として引く。

## 既存ページを見直す

モデルやツールが更新されたら、再現手順をやり直します。結果が変わった場合は、検証日とモデルを更新し、変わった点を「結果」に書きます。再現しなくなった知見は削除せず、「見直す条件」に該当したことを冒頭に書きます。
