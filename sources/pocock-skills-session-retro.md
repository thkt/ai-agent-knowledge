## 中心の主張

**人の価値は、最初の合わせ込みと、最後の基準の適用にある。** 動画は、間の実装を agent に任せ、人は言葉を決める段と、仕組みを直す段に時間を使う様子を見せる。

## 流れ

| 段 | やること | 残るもの |
| --- | --- | --- |
| 聞き取り（`grill-with-docs`） | 作るものではなく、困りごとを口頭で伝える。agent が番号つきの問いを出し、用語集と ADR を読んで聞く。名前で揉めた所は、1 問ずつに切り替える | 用語集の更新、ADR |
| 試作 | 使い心地の判断が要る所は、別の agent が 3 案を作る。人が触って 1 つを選ぶ | 試作のブランチ |
| 仕様と分割（`to-spec`、`to-tickets`） | 仕様を Issue にする。利用者の話が約 47 件、実装で決めたこと、範囲外を持つ。子の Issue に分け、依存を付ける | 仕様の Issue と、子の Issue |
| 実装（`implement-spec`） | 文脈を畳んでから、離席する。1 つの subagent に 1 つの子の Issue を渡し、着手できるものから並列で進め、1 つの PR にまとめる。agent のレビューと、基準との照合まで行う | 約 21,000 行の PR |
| 人のレビュー | PR を 7 本に割らせ、GitHub で全行を読み、コメントを 12 件付ける | レビューのコメント |
| 振り返り（`retro`） | セッションの記録 30 数件と、コメント 12 件を、複数の agent が読む | 重い順の改善の一覧、Issue |

| 聞き取りの終わりは、人が決める | 目安は、答えが「同意」の連続になることである | 動画の発言だけである |

## 実演で、振り返りが出したもの

- 12 件のコメントの原因は、1 つだった。守らせたい書き方が基準のどこにも無く、main には、やめたい書き方の例が数千あった。
- 手当ては、後戻りしない検査である。今ある違反の数を上限にして、増えたら落とす。対象は、型の言い切り（`as`）、`useEffect`、生の `fetch`、検索の引数の文字列などである。
- 試作のコードが、作り直されずに写されていた。
- レビューの agent が、大きい差分を 1 つでは覆えていなかった。
- 結果は Issue にした。skill が原因のものは、skill の repo へ回した。

## 限界

- **1 回の実演である。** 対象は、本人の個人のアプリである。普段は確かめずに merge する、今回は本番を装った、と本人が言う。
- **数字は、口頭の値である。** PR の行数は、投稿では 21,000 行、動画の冒頭では「たしか 25,000 行」と言う。
- **全行を読むレビューは、普段はしない。** 視聴者向けの実験で、専用の skill も無い、と本人が言う。
- **作られた PR のその後は、分からない。** 手で触って、顔の移動が敏感すぎる、と言う場面がある。
- **文字起こしは、機械によるものである。** 道具とモデルの名前に、聞き間違いがある。1 回目は 25 分あたりで壊れたので、25 分から後ろを 8 分ずつ起こし直した。つなぎ目の前後は、欠けている可能性がある。
- **照合者は、文字起こしを通しては読んでいない。** 2 つの agent の要約を読んだ。画面に映ったコードと図は、見ていない。

## 照合の結果

- **照合した主張：** 振り返りの skill の 7 つの種類、検査を既定にすること、指示のファイルの使い方は、repo の本文で確かめた。動画の中の発言は、動画の中の記述だけである。
- **読んでいないもの：** 動画の画面。`grill-with-docs`、`to-spec`、`to-tickets`、`implement-spec` の本文。repo の `docs/` の説明。
- **確かめていないもの：** 動画の数字。実演の PR と Issue の実物。

## 照合の手順

1. 投稿を取得する：`xr tweet <出典の URL>`。動画の URL が出る。
2. 音声を文字に起こす：`xr tweet <出典の URL> --transcribe --lang en`。70 分を一度に起こすと、途中から同じ語の繰り返しになった。
3. 壊れた所から後ろを、起こし直す。`ffmpeg` で、音声を 8 分ずつに切る。`whisper-cli` に、前の文脈を引き継がない指定（`-mc 0`）を付けて、1 つずつ起こす。
4. 文字起こしを agent に読ませ、流れ、skill、レビュー、主張、数字、留保に分けた要約を受け取る。
5. 振り返りの skill の本文を読む：`scout repo-read mattpocock/skills skills/engineering/retro/SKILL.md`。

## 見直す条件

- 手元で、レビューのコメントとセッションの記録から、仕組みの欠けを探す回を行ったとき。結果を `knowledge/` に書く。
- 手元の決まりの文を、検査に置き換えたとき。置き換えた前後で、同じ指摘が出る回数を比べる。
- 残りの skill の本文を読んだとき。流れの表の、残るものの列を、本文で確かめ直す。
