# くまぎの投稿「Lean の証明つきで SQL のオプティマイザを速くした」の考え方と根拠（2026-11）

くまぎ（@kumagi）が X に、Lean を書いたことが無いまま、Gemini 4 に SQL のオプティマイザの高速化を頼んだ結果を投稿した。投稿と、スレッドに出た本人の返信と、ほかの人の返信を照合した。自分たちが採用した判断ではない。依頼者は、この考え方を feedback-loop と cantle で使うことを検討している。

## TL;DR

- 投稿によれば、Gemini 4 は既存の最適化ルールすべてに Lean の証明を付け、証明付きの最適化を4つ足し、TPC-DS が1.7〜2.5倍速くなった。
- 照合者の読みでは、速さを生んだのは足した最適化で、証明は「書き換えても結果が変わらない」根拠として働いた。
- 本人の返信によれば、証明をコードに落とすときに agent がバグを入れ、本人がかなり見つけて直している。証明が覆うのはモデルで、実装ではない。
- 数字は本人の要約で、オプティマイザ、規模、測り方、証明、コードは公開されていない。

- **根拠は、本人の要約1件である。** 依頼と返答は会話の形に要約されていて、agent の実際の出力は示されない。
- **再現できない。** 対象のオプティマイザ、証明、コード、TPC-DS の規模と測り方が公開されていない。
- **証明の範囲が分からない。** 何を証明したか（書き換えの前後で結果が等しいこと、などの性質）と、証明が検査を通ったかが書かれていない。
