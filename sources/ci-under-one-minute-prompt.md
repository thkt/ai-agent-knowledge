# 「CI を 1 分以内にする。ただし嘘をつかせない」という agent 向けのプロンプトと、手元で測った結果（2026-11）

Pontus Abrahamsson は X に、CI を速くするために agent に渡すプロンプトを画像で投稿した。プロンプトの全文を読み、道具についての記述を Bun の canary で確かめ、手元の 4 つの repo の CI の時間を測った。プロンプトそのものは、手元で使っていない。自分たちが採用した判断ではない。

## TL;DR

- 中心は、速さより優先する 3 つの決まりである。main に入る前に全テストを走らせる。失敗を隠さない（やり直し、時間切れの延長、skip をしない）。検査を減らさない。
- 進め方は、先に測ることである。直近 150 回の実行を、待ち、準備、実行に分け、いちばん大きい所から直す。道具を替えるときは、新旧を並べて走らせ、新しいほうが見逃すものを挙げる。
- `bun lint` は、Bun の正式版（1.4.5）には無く、canary（1.4.6-canary.1）にあった。手元の repo の clone で、oxlint の 89 ミリ秒が 26 ミリ秒になり、わざと入れた違反 4 件の指摘は同じだった。
- 手元の CI で、中央値が 1 分を超えていたのは 1 つだけだった。別の 1 つは、CI が起動していなかった。
- 投稿が書く効果（週に 200 時間以上の待ち時間が減った）の測り方は、示されていない。照合日は 2026-11-23。

## 中心の主張

**CI は、速くしてよい。ただし、速くするために検査を弱めてはいけない。** プロンプトは、目標（PR の結果が中央値で 1 分以内、95 パーセンタイルで 2 分以内）より先に、破ってはいけない決まりを 3 つ置く。

## 考え方と根拠

| 考え方 | プロンプトの記述 | 照合の結果 |
| --- | --- | --- |
| 全テストは、main に入る前に走らせる | merge queue で全テストを走らせる。テストの選択は、PR の結果を早く返すためだけに使う | プロンプトの記述だけである。[openclaw-ci-cost-reduction.md](openclaw-ci-cost-reduction.md) も、関係が分からなければ範囲を広げる、と同じ向きを書く |
| 失敗を隠さない | やり直し、時間切れの延長、テストの skip をしない。やり直しが要る検査にはバグがあるので、それを見つける | プロンプトの記述だけである |
| 検査を減らさない | lint の規則と必須の検査は、保つか増やすかだけにする | プロンプトの記述だけである |
| 先に測る | 直近 150 回の実行を、待ち、準備、実行に分け、中央値と 95 パーセンタイルを出す。いちばん大きい所から直す | プロンプトの記述だけである |
| 段ごとに、時間の上限を決める | 待ち、準備、lint、format、型検査、テストのそれぞれに秒数の上限を置き、超えた job を失敗にする | プロンプトの記述だけである。上限の数字の根拠は、書かれていない |
| 道具を Bun にそろえる | lint は `bun lint`、format は `bun fmt`、型検査は `bun check`、テストは `bun test` にする。`bun lint` は、今ある `.oxlintrc.json` を読む | 手元で確かめた。次の節に書く |
| 道具を替えるときは、並べて走らせる | 挙げた道具は既定で、古い道具を残すには測った理由が要る。切り替える前に、新旧を並べて走らせ、新しいほうが見逃すものを挙げる | プロンプトの記述だけである。手元では同じ日に、自前の実装と既存の道具を同じ対象で比べ、片方だけが拾うものの中身を確かめた |
| テストを減らすのは、記録に基づく | 2 週間、直したテストの失敗を「回帰を捕まえた」か「変更に反応しただけ」かで記録する。後者だけのファイルを消す。認可、プライバシー、migration、並行性のテストは消さない | プロンプトの記述だけである |
| テストの選択は、わざと隠して確かめる | PR では、差分から届くテストだけを走らせる。その後、本物の変更をわざと隠して、CI が赤になることを確かめる | プロンプトの記述だけである |
| 手元の検査は、hook にする | commit の前と push の前の hook で、CI と同じ検査を走らせる。`AGENTS.md` の 1 行にしないのは、agent が手順を飛ばすからである | プロンプトの記述だけである |
| 1 つの変更を、1 つの小さい PR にする | 実際の実行での、前と後の数字を付ける。口座、秘密の値、費用が増えることは、まとめて人に持ってくる | プロンプトの記述だけである |

## 手元で確かめたこと

### `bun lint` があるか

| Bun の版 | `bun lint` | `bun fmt` | `bun check` |
| --- | --- | --- | --- |
| 1.4.5（2026-11-19 の正式版） | 無い | ある | ある |
| 1.4.6-canary.1（2026-11-23 の canary） | ある | ある | ある |

投稿の作者は、返信で「Bun 1.5 が出たら `bun lint` に切り替える」と述べている。Bun 1.5 の公開日は、確かめていない。

### 速さと、拾うもの

canary を一時ディレクトリに置き、手元の repo（Cantle）の clone で比べた。lint の対象は 393 ファイルで、`.oxlintrc.json` を持つ。

| 走らせ方 | 中央値（7 回） | 最小 |
| --- | --- | --- |
| oxlint 1.89.0（`node_modules/.bin/oxlint`。Node.js の起動を含む） | 89 ミリ秒 | 81 ミリ秒 |
| `bun lint --no-script`（canary） | 26 ミリ秒 | 24 ミリ秒 |
| `bun lint --no-script --type-aware`（canary、5 回） | 271 ミリ秒 | 266 ミリ秒 |

- 未使用の import、未使用の変数、未使用の catch の引数、`debugger` を入れたファイルを 1 つ置いた。両方が、同じ 4 件を、同じ規則、同じ位置、同じ文言で指摘した。
- canary の `bun lint --doctor` は、「96 の規則がネイティブで走る。15 の規則は型が要るので、`--type-aware` を付けないと走らない。oxlint は外せる」と報告した。
- `--type-aware` を付けると、今の設定のままで警告が 1 件出た。今の oxlint の実行では、出ていない警告である。

### 手元の CI の時間

4 つの repo の、直近 40 回の実行を、作成から完了までの時間で数えた。

| repo | 中央値 | 最長 | 失敗 |
| --- | --- | --- | --- |
| dotclaude | 9 秒 | 648 秒 | 0 件 |
| recall | 23 秒 | 716 秒 | 1 件 |
| feedback-loop | 155 秒 | 174 秒 | 0 件 |
| Cantle | 3 秒 | 4 秒 | 40 件 |

- Cantle は、40 件が 3 秒ほどで失敗していた。job が起動していない。支払いの問題だと、別の Issue に記録がある。
- dotclaude と recall の中央値は、テストを走らせない短い実行を含む。テストを走らせた実行だけの値は、数えていない。

## 手元の設定との差

| 差 | 根拠 |
| --- | --- |
| lint の時間は、既に目標を満たしている | プロンプトの上限は 1 秒である。手元の oxlint は 0.1 秒かからない。`bun lint` にしても、縮むのは 60 ミリ秒ほどである |
| 型が要る規則が、今は走っていない | 設定には 15 個あるが、oxlint の実行では走っていない。`bun lint --type-aware` なら 0.27 秒で走る。切り替えの利点は、速さより、この 15 個が走ることにある |
| 負荷で落ちるテストを、1 件ずつ直してきた | Cantle の、2026-10-24 以降の Bug の Issue 21 件のうち、11 件が「負荷の高いときにテストが時間切れになる」だった。その直し方が、時間切れを延ばす形だったかは、読んでいない。延ばしていたなら、プロンプトが禁じる形である |
| テストを減らす根拠を、数えていない | 手元は、Bug の出どころは読み分けたが、テストの失敗を「回帰を捕まえた」か「変更に反応しただけ」かでは記録していない |
| 手元の検査の一部は、指示の 1 行である | 同じ日に、複数の agent が 1 台のマシンを使うときの決まりを、agent 向けの指示ファイルに 3 行で足した。hook ではない |

## 限界

- **効果の測り方が、示されていない。** 「週に 200 時間以上」が、どの repo の、どの期間の値かは、書かれていない。
- **プロンプトを、使っていない。** 手元の repo に、このプロンプトで agent を走らせてはいない。
- **拾うものの比較は、1 ファイルの 4 件だけである。** 96 の規則の全部で、oxlint と同じ結果になるかは、確かめていない。
- **canary は、毎日変わる版である。** 測ったのは、2026-11-23 の版である。
- **外部のサービスは、調べていない。** プロンプトが挙げる runner のサービスと、hook の道具は、費用も動きも確かめていない。

## 照合の結果

- **照合した主張：** 「`bun lint` は `.oxlintrc.json` を読む」は、canary で確かめた。「lint は 1 秒以内」は、手元の repo では oxlint でも満たしていた。
- **読んでいないもの：** プロンプトが挙げる外部のサービスの文書。Bun の `bun lint` の文書。
- **範囲外：** runner の乗り換え、shard の分け方、テスト用のデータベースの持ち方。

## 照合の手順

1. 投稿を取得する：`xr tweet https://x.com/pontusab/status/2123771160261529982`。画像の URL が出る。
2. 画像を取得して読む。返信の 1 つが、全文を文字に起こしている。画像と照らして、同じ内容であることを確かめた。
3. 正式版に `bun lint` があるかを見る：`bun --help`。
4. canary を一時ディレクトリに置く：`gh release download canary -R oven-sh/bun -p 'bun-darwin-aarch64.zip'`。展開した `bun` を、パスを指定して呼ぶ。手元の Bun は変えない。
5. 速さを測る：repo の clone で、`node_modules/.bin/oxlint` と `<canary>/bun lint --no-script` を 7 回ずつ走らせ、壁時計の時間の中央値を取る。`--no-script` を付けないと、`package.json` の `lint` の script が走る。
6. 拾うものを比べる：違反を入れたファイルを 1 つ置き、両方に渡す。比べた後に、ファイルを消す。
7. 走る規則を見る：`<canary>/bun lint --doctor`。
8. CI の時間を数える：`gh run list -R <repo> --limit 40 --json createdAt,updatedAt,conclusion,status`。

## 見直す条件

- Bun の正式版に `bun lint` が入ったとき。手元の repo で、oxlint との指摘の差を全ファイルで比べてから、切り替えるかを決める。`--type-aware` で出る警告も、そのときに扱う。
- Cantle の CI が起動するようになったとき。CI の時間を測り直す。
- 負荷で落ちるテストの直し方を読んだとき。時間切れを延ばしていたかを、`knowledge/` に書く。
