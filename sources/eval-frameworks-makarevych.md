## 中心の主張

**eval の道具は、順位ではなく、合うかどうかで選ぶ。** 記事は、道具ごとに、利用者の手から外れる仕事と、利用者が作り続ける仕事を並べる。少人数で agent が 1 つのチームと、本番の通信とリリースの関門を持つチームでは、要る棚が違う、と書く。

## 考え方と根拠

| 考え方 | 記事の記述 | 照合の結果 |
| --- | --- | --- |
| eval は、同じ検査を繰り返し、数字で判断するためのものである | モデルは、流暢に間違える。良い答えを 1 つ読んでも、次の 100 個については何も分からない | 記事の記述だけである |
| eval は 4 つの部品でできている | 入力の集まり、試す対象、判定、実行の記録である。道具を使わず手で作るときも、4 つとも作る | 記事の記述だけである。ほぼ全部の道具がこの 4 つを求める、と書く |
| 採点する高さを、先に決める | 最終の答え、1 つの手順、tool の選び方、経路の全体、会話、検索と生成の分離、費用と遅延は、別々の検査である | 記事の記述だけである |
| 採点役は 4 種類ある | コードの規則、判定役のモデル、選択と確率を返す型つきのモデル、人である | 記事の記述だけである |
| 採点役も、採点される対象である | eval には、数字が 2 つ要る。製品の出来と、採点役が人と一致する割合である。確かめていない採点役の点数が、チームが自分をだます、いちばん多い形だと書く | 記事の記述だけである。一致の割合の目安は、示されていない |
| 使う時期は 3 つある | 公開の前は、動くかを知る。変更のたびに、後退を捕まえる。公開の後は、本番の通信から、試験の集まりが見逃した失敗を見つける | 記事の記述だけである |
| コードで書く道具は、tool と状態を持つ agent に合う | 差は、指標の数ではなく、対象を動かす層にある。tool、sandbox、やり直しが要るなら、この種類を選ぶ | 記事の記述だけである |
| 設定で書く道具は、比べやすさと速さを買う | 深さは買えない。agent の経路、判定役のモデル、関門は持たないものが多い | 記事の記述だけである |
| 基盤の強みは、失敗をデータにして関門にする循環である | データと実験に版を付ける。判定役を人と合わせてから、自動にする | 記事の記述だけである |
| 観測の道具は、良し悪しを言わない | 経路は見えるが、判定には、閾値を持つ判定役を足す。本番では正解なしの検査、手元では正解つきの検査を使う | 記事の記述だけである |
| 検索の指標は、悪い場所を教える | 検索と生成を分けて採点する。履歴と関門は、別の仕組みに持たせる。点は走らせるたびに少し変わるので、小さい集まりを 2 回流してばらつきを記録してから、関門を信用する | 記事の記述だけである |
| 行動を変えない決まりは、捨てる | まとめの各行を、チームの決まりとして持つ。何を作るか、何を merge の前に止めるかを変えない決まりは、外す | 記事の記述だけである |

## 道具の並び

記事が挙げる、道具ごとの「得られるもの」と「自分で作るもの」である。記事の記述を写したもので、各道具の文書とは照らしていない。

| 種類 | 道具 | 得られるもの | 自分で作るもの、または制約 |
| --- | --- | --- | --- |
| コードで書く | Inspect | agent を動かす層、sandbox、繰り返し | 経路と検索の指標、実験の比較、本番の採点 |
| コードで書く | DeepEval | 経路、検索と生成の分離、会話の指標の一覧。テストとして走る | sandbox、繰り返し。経路の指標は、専用の追跡が要る |
| コードで書く | Pydantic Evals | 型つきの case、case ごとの判定役、本番の抜き取り | 既製の指標が少ない。手元で動く tool しか見えない |
| skill 専用 | SkillEvaluator | skill のファイルと、skill のあり、なしでの差を採点する | 新しく、実験的である。skill だけが対象で、ほかの道具と組む |
| 設定で書く | lm-evaluation-harness | 再現できる数字。seed、キャッシュ、繰り返し | agent、tool、判定役、関門、追跡を持たない |
| 設定で書く | Promptfoo | prompt とモデルの総当たり、攻撃側の試験 | 履歴の一元管理、本番の採点 |
| 設定で書く | OpenAI Evals | データ、論理、設定を 3 層に分ける形 | 提供元の側の経路が終了に向かう。新しくは採らない、と記事が書く |
| 一覧 | HELM | 何を測るかの点検表 | 保守だけの状態で、関門には使えない |
| eval が中心の基盤 | Braintrust | 版つきのデータ、比較、本番の規則、関門 | 繰り返しの統計、領域の指標。中心は提供元の側で動く |
| eval が中心の基盤 | MLflow GenAI | 自分で置ける。追跡からデータを作る、判定役の調整、関門 | サーバーと SQL の保存先 |
| 観測が中心 | Langfuse | 本番と手元の循環、費用の上限 | 指標が少ない |
| 観測が中心 | LangSmith | 2 つの出力の比較、会話の単位の採点 | 自分では置けない |
| 観測が中心 | Phoenix | 経路の検査の雛形、再生 | 本番の規則と関門は、自分で書く |
| 観測が中心 | TruLens | 判定役の比較と、調整の手順 | 基盤としての循環が薄い |
| 表の検査 | Evidently | 行ごとの検査の一覧、関門 | 経路の検査を持たない |
| 検索専用 | Ragas | 検索と生成を分けた 4 つの数字 | 履歴、関門、追跡、本番の循環 |

記事は、SkillEvaluator の規則の数（500 超）と、Evidently の検査の数（100 超）を、提供元の主張として書く。

## 限界

- **新しい測定が無い。** 記事は冒頭で、モデルを走らせていないと断る。チームごとに進め方が違うので、1 つの例が型として読まれるのを避けた、と理由を書く。
- **道具の記述の出どころは、提供元の文書である。** 参考文献 20 件の内訳は、公式の文書とサイトが 16 件、repo が 4 件である。第三者の比較は、含まれていない。
- **版と日付が無い。** 道具の版の番号と、文書を確かめた日は、書かれていない。道具の機能は変わるので、記述は公開日の時点のものとして読む。
- **対象は、モデルを組み込んだ製品である。** agent に渡す決まりと skill を作る側に当たるのは、SkillEvaluator の 1 つだけである。
- **照合の一部は、要約に頼っている。** 6 つの段の本文は、agent の要約を通して読んだ。
