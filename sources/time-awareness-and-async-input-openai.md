# OpenAI の、エージェントに現在時刻を知らせ、返事を待つ間も作業を続けさせる考え方と根拠（2026-11）

OpenAI の開発者ブログは、締め切りのある作業をエージェントにさせる方法として、時間認識と非同期の関数ツールを紹介する。記事の記述を、記事が引く API の手引きと照合し、自作のエージェントハーネス（Cantle）のコードに当てはめた。自分たちが採用した判断ではなく、手元では動かしていない。

## TL;DR

- 中心の主張は 2 つある。モデルに現在時刻を繰り返し知らせれば、モデルは締め切りに合わせて進め方を変えられる。利用者への質問を非同期のツールにすれば、返事を待つ間も作業を続けられる。
- Agents API では、設定 `experimental.time_awareness: true` が現在時刻を知らせる。Responses API を自分のループで使う場合は、要求のたびに `Current time: <UTC の時刻>.` を developer のメッセージとして足す。
- 非同期のツール（`async: true`）は、Responses API の関数ツールでも使える。手引きは、対応するモデルを「GPT-6 Astra 以降」と書く。
- Cantle は、依頼の全体に時間の上限を持つが、モデルに時刻も残り時間も知らせていない。上限に達すると、途中で打ち切る。
- 時刻を知らせると結果が良くなるかの測定は、記事に無い。Cantle でも試していない。照合日は 2026-11-23。

## 中心の主張

**締め切りのある作業では、モデルが「今が何時か」と「返事がまだ来ていないこと」を知ったうえで、次に何をするかを決める。** 記事の題材は、15 分後の打ち合わせに向けて、12 分以内に相手企業の資料を作らせる場面である。エージェントは打ち合わせの目的を利用者に尋ね、返事を待つ間も調査を続け、返事が来なくても資料を仕上げる。

## 考え方と根拠

| 考え方 | 原文の記述 | 照合の結果 |
| --- | --- | --- |
| 現在時刻を繰り返し知らせる | Agents API の `experimental.time_awareness` を `true` にすると、検索の結果や利用者の入力を待つ間も、モデルに現在時刻が伝わる。締め切りが近ければ、新しい調査より、裏付けと書き上げを優先できる | 記事の記述だけである。設定の名前が示すとおり、実験的な機能である。通知の間隔と形式は、記事に書かれていない |
| 時刻は絶対時刻で渡す | 「15 分後」「3 分残す」を、アプリケーションが絶対時刻に直してから渡す。モデルとアプリケーションが同じ時刻を参照するためである | 記事の記述だけである |
| 自分のループでは、要求のたびに時刻を足す | Responses API を自分のループで使う場合は、モデルへの要求の直前に毎回、現在の UTC の時刻を developer のメッセージとして足す。ツールの結果を送る要求も含む。締め切りは最初に 1 回だけ計算し、会話履歴に残す | 記事のコードに `Current time: ${new Date().toISOString()}.` の形がある |
| 利用者への質問を、非同期のツールにする | 関数ツールに `async: true` を付けると、アプリケーションが回答を受け付ける間も、エージェントは作業を続ける | 手引きに記述がある。通常の関数の呼び出しは、ツールの応答を待って turn を止める。`async: true` のツールは、出力が返る前にモデルが作業を続ける。ツールを実行するのはアプリケーションで、OpenAI の側ではない |
| 非同期のツールは Responses API でも使える | 記事は Agents API の例を中心に書く | 手引きは Responses API の言葉で書かれている。結果は後の要求の `function_call_output` として、元の `call_id` で返す。続きの要求では `previous_response_id` に最新の応答の ID を入れる |
| 回答に期限を設け、未回答をはっきり返す | 提出の 2 分前に質問を締め切り、未回答なら `{"status":"no_answer"}` を返す。回答があれば `answered` と回答を返す | 手引きにも記述がある。非同期の実行は、利用者が答えるまで応答を開いたままにしない。質問を閉じたり期限で切ったりするなら、未回答を明示した結果を返し、モデルに進め方を決めさせる |
| 「質問を表示した」を結果にしない | （記事には無い） | 手引きに記述がある。ツールの結果は利用者の回答であり、表示したことの確認で呼び出しを終わらせない |
| 期限はアプリケーションが守る | 提出の期限が先に来たら、その時点の最新版を返す。ループの開始から終了まで、アプリケーションの側でタイマーを動かす | 記事の記述だけである |

## Cantle に当てはめたときの差

| 差 | 根拠 |
| --- | --- |
| Cantle は、時間の上限を持つが、モデルに知らせていない | 依頼の全体の上限から残り時間を計算し、`AbortSignal.timeout` で打ち切る（[src/agent.ts L109-L113](https://github.com/thkt/cantle/blob/495ed43/src/agent.ts#L109-L113)）。上限に達すると、失敗を `agent_budget`、`time_limit` と記録する（[L278-L283](https://github.com/thkt/cantle/blob/495ed43/src/agent.ts#L278-L283)）。`src/` に、現在時刻や残り時間をモデルに渡す箇所は無い |
| 非同期のツールを、今のモデルで使えるかは分からない | 手引きは、対応を「GPT-6 Astra 以降」と書く。Cantle の OpenAI のモデルは `gpt-6.1-sol` と `gpt-6-sol` である（[src/responses.ts L11-L12](https://github.com/thkt/cantle/blob/495ed43/src/responses.ts#L11-L12)）。この 2 つが対応するかは確かめていない |
| 非同期のツールの続け方が、Cantle の要求の形と合うかは分からない | 手引きは、続きの要求に `previous_response_id` を使う。Cantle は `store: false` で要求する。保存しない要求で非同期のツールを使えるかは、手引きに書かれていない |
| 時刻を足すと、プロンプトのキャッシュに影響しうる | 要求のたびに違う文字列が入力に入る。記事の形（入力の末尾に足す）なら、それより前の部分は変わらない。Cantle でキャッシュが当たっているかは、cantle #290 で調べる予定である（照合者の推測） |

## 限界

- **効果の測定が無い。** 時刻を知らせたときに、締め切りを守る割合や資料の質がどう変わるかの数字は、記事にも手引きにも無い。
- **時間認識は実験的な設定である。** 記事は `experimental` の下の設定として示す。
- **記事のコードは読んでいない。** 本文だけを読んだ。`Current time:` の行と `no_answer` の行だけ、コードで確かめた。
- **手元で動かしていない。** Agents API も、非同期のツールも、試していない。

## 照合の結果

- **照合した主張：** 「考え方と根拠」の非同期のツールに関する行は、手引きの本文と照合した。時間認識に関する行は、記事の記述だけで、ほかの資料とは照合していない。
- **読んでいないもの：** 記事のサンプルコードの全体、Agents API の手引き（設定、セッション、イベント）、関数ツールの手引き。
- **範囲外：** dot の製品としての説明。

## 照合の手順

1. 記事を取得する：`scout fetch https://developers.openai.com/ja-JP/blog/time-awareness-and-async-input-for-personal-agents`
2. コードの外の本文だけを読む：取得した Markdown から、コードの囲みの中を除く。
3. 非同期のツールの手引きを取得する：`scout fetch https://developers.openai.com/api/docs/guides/async-tool-calling`
4. Cantle の上限の扱いを読む：`src/agent.ts` の `deadline` と、`time_limit` を記録する箇所を読む。
5. Cantle が時刻をモデルに渡していないことを確かめる：`ugrep -rn -i 'current time' src/` で、何も出ないことを見る。

## 見直す条件

- 時間認識が `experimental` でなくなったとき、または通知の形式が文書に書かれたとき。
- Cantle で、時刻と残り時間を足した場合と足さない場合を比べたとき。結果は `knowledge/` に書く。
- Cantle が使うモデルで、非同期のツールが使えると分かったとき。
